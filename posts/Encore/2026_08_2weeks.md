# 8/10 ~ 8/14 주간회고

이번 주는 Python이라는 언어 자체를 배우는 것에서 시작해, 실제 API를 만들고 외부 API를 호출하는 단계까지 꽤 빠르게 범위를 넓혔다.

처음에는 Module, Package, Library, Class, Exception 같은 기본 개념과 PEP 8, Ruff, pip 같은 Python 생태계부터 정리했다. 모바일 개발을 오래 해온 입장에서 개념 자체가 새롭다기보다는, 이미 알고 있던 구조가 Python에서는 어떤 방식으로 표현되는지를 대응시키는 과정에 가까웠다. 특히 문법을 외우는 것보다 패키지를 어떻게 관리하고, 코드 스타일과 개발 환경을 어떻게 구성하는지가 앞으로 더 중요하겠다는 생각이 들었다. 

Git과 GitHub는 익숙한 영역이지만 merge conflict 해결이나 GitHub Project, Actions까지 다시 다뤄보면서 개발 과정 전체를 한 번 정리할 수 있었다. 이후 REST API와 FastAPI로 넘어가면서 로컬 서버를 띄우고 도서 목록, 상세 조회, 검색 기능을 직접 구현했다. 이 시점부터는 단순한 Python 학습보다는 기존에 해왔던 클라이언트 개발의 반대편을 직접 만들어보는 느낌이 강해졌다.  

Pydantic의 BaseModel, Field, field_validator와 `*`, `**` 언패킹, List Comprehension 등을 배우면서 Python 특유의 표현도 조금씩 익숙해지고 있다. 특히 Pydantic을 보면서 모바일에서 모델을 정의하고 validation을 처리하던 경험과 비교해보니 이해가 훨씬 빨랐다. 마지막으로 `urllib`, `requests`, `httpx`의 차이를 살펴보고 Open-Meteo API까지 호출하면서, 이번 주에 배운 내용들이 하나의 흐름으로 연결되기 시작했다.  

아직 Python다운 코드를 작성한다고 말하기는 어렵다. 익숙한 언어의 사고방식으로 먼저 접근한 뒤 Python 문법으로 번역하는 단계에 가깝다. 그래도 문법을 오래 붙잡기보다 실제 서버와 API를 만들면서 필요한 개념을 채우는 방식이 현재로서는 효율적이다. 다음 단계인 Supabase와 PostgreSQL까지 연결되면 단순 예제를 넘어 하나의 작은 백엔드 구조를 직접 구성해볼 수 있을 것 같다.

## ✅ 4L

**Liked : 좋았던 점**  
Python 기초만 반복하지 않고 FastAPI와 외부 API 호출까지 빠르게 연결해본 점이 좋았다. 기존 모바일 개발 경험과 비교하면서 배우니 새로운 개념도 생각보다 빠르게 구조화할 수 있었다.

**Lacked : 부족했던 점**  
문법과 라이브러리를 개별적으로 이해하는 데 집중하다 보니 아직 전체 구조를 혼자 처음부터 구성하는 경험은 부족하다. 특히 Python 특유의 간결한 표현은 더 익숙해질 필요가 있다.

**Learned : 새롭게 배운 점**  
Python의 패키지 관리와 개발 도구, FastAPI의 기본 구조, Pydantic을 이용한 모델 정의와 validation, HTTP 라이브러리와 외부 API 호출 흐름을 익혔다. Python 생태계가 생각보다 역할별로 명확하게 나뉘어 있다는 점도 흥미로웠다.

**Longed for : 앞으로 더 해보고 싶은 점**  
다음 주에는 Supabase와 PostgreSQL을 연결해 데이터를 실제로 저장하고 조회하는 흐름까지 만들어보고 싶다. 이후에는 FastAPI를 중심으로 작은 서비스를 하나 완성하면서 지금까지 배운 내용을 한 번에 정리해보고 싶다.
