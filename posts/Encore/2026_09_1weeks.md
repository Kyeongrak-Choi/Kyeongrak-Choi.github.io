이번 주는 지금까지 배운 기술들을 정리하면서, 본격적인 프로젝트를 시작하기 위한 준비 작업에 조금 더 무게를 둔 한 주였다.

Pandas를 다루고 챗봇 프론트엔드를 만들면서 단순히 백엔드 기능만 구현하는 것에서 벗어나, 데이터를 어떻게 보여주고 사용자와 어떻게 연결할지도 같이 보기 시작했다. 이후에는 Gemini를 백엔드와 연결하고 실제 챗봇 형태로 동작시키면서 이전까지 따로 배웠던 FastAPI, LLM, Streamlit이 하나의 흐름 안에서 조금씩 맞춰졌다.

Render와 Streamlit Cloud를 이용해 직접 배포까지 해본 것도 의미가 있었다. 로컬에서 잘 돌아가는 것과 외부에서 실제로 접근 가능한 서비스로 만드는 것은 역시 다른 문제였다. 환경변수나 API 연결처럼 평소에는 크게 신경 쓰지 않았던 부분이 배포 단계에서는 바로 문제로 드러났다. 프로젝트에 들어가기 전에 이런 부분을 미리 경험한 것이 오히려 다행이라고 생각한다.

챗봇의 맥락을 얼마나 유지할지 고민한 것도 기억에 남는다. 대화를 많이 보내면 품질에는 도움이 될 수 있지만 응답 속도와 토큰 사용량이 늘어난다. 결국 무조건 많이 넣는 것이 좋은 게 아니라 필요한 정보만 남기는 기준이 필요했다. `yield`와 generator도 처음에는 Python 문법 중 하나로만 보였는데, 스트리밍 응답과 연결해서 생각하니 왜 필요한지 조금 이해됐다.

이번 주에는 수업 외에도 프로젝트를 시작하기 위한 선수작업을 같이 진행했다. 프로젝트 구조와 역할, 필요한 기능을 미리 정리하고 실제 개발에 들어갔을 때 막힐 만한 부분들을 먼저 확인했다. 예전에는 일단 만들면서 정리하는 쪽에 가까웠다면, 이번에는 짧은 프로젝트일수록 초반 설계와 준비가 오히려 시간을 줄여준다는 쪽에 더 무게가 갔다.

 좋은 모델 하나를 호출하는 것이 끝이 아니라 Context, Tool, Retry, Cache, Fallback 같은 주변 구조까지 어떻게 설계하느냐가 결국 서비스 품질을 결정한다. 앞으로 프로젝트에서 LLM 파트를 맡으면서 가장 신경 써보고 싶은 부분이기도 하다.

### ✅ 4L

**👍 Liked**  
배웠던 기술들이 실제 챗봇과 프로젝트 구조 안에서 하나씩 연결되기 시작한 점이 좋았다.

**🤔 Lacked**  
기능 구현 자체보다 배포, 맥락 관리, 프로젝트 구조처럼 주변에서 결정해야 할 것이 생각보다 많았다. 아직은 경험으로 판단하기보다 하나씩 확인하면서 가는 단계다.

**📚 Learned**  
LLM 개발도 결국 모델 호출만 잘한다고 되는 게 아니었다. Context와 실행 흐름, 실패 처리까지 포함한 주변 시스템 설계가 꽤 중요하다.

**🚀 Longed for**  
이번에 준비한 선수작업을 바탕으로 실제 프로젝트에서는 기능을 많이 넣기보다 구조를 제대로 잡고, LLM 파트를 하나의 독립된 시스템처럼 만들어보고 싶다.
