이번 주는 AI Agent를 만드는 과정에서 개발 자동화와 보안까지 조금 더 넓게 살펴본 시간이었다. 지난주 Docker와 AWS 배포를 배우면서 실행 환경에 대한 이해를 넓혔다면, 이번에는 코드를 수정한 이후 테스트와 배포가 어떻게 이어져야 하는지에 집중했다.

GitHub Actions를 이용한 CI/CD 실습이 가장 기억에 남는다. 코드를 Push하면 테스트가 실행되고, 정상적으로 통과했을 때 AWS 배포까지 이어지는 구조를 직접 다뤘다. 모바일 개발에서도 빌드 자동화나 배포 파이프라인은 익숙한 개념이라 전체적인 흐름은 어렵지 않았다. 다만 Python 프로젝트에서 pytest를 실행하고 Docker 이미지를 빌드해 AWS에 배포하는 과정은 처음이라 설정 하나하나를 확인해야 했다. 특히 로컬 Docker 환경에서 문제가 발생하면서 자동화도 결국 각 단계의 실행 환경이 제대로 준비되어 있어야 의미가 있다는 걸 다시 확인했다.

3-file-system을 통해 PRD와 Tasks를 작성하는 방식도 살펴봤다. AI를 활용해 개발할 때 무작정 코드를 생성하는 것보다 요구사항과 작업 단위를 먼저 정리하는 게 중요하다는 생각이 들었다. 기존에도 설계와 작업 분리는 당연하게 해왔지만, AI에게 일을 맡기는 상황에서는 그 기준을 더 명확하게 전달해야 한다. 그렇지 않으면 코드가 빠르게 만들어져도 내가 의도한 방향과 달라질 수 있다.

후반에는 Moderation API와 프롬프트 인젝션 방어를 공부했다. 이전까지는 Agent가 사용자의 요청을 얼마나 잘 수행하는지가 주요 관심사였다면, 이제는 어떤 요청을 허용하고 어디서 제한해야 하는지도 고려하게 됐다. Moderation API가 유해 콘텐츠를 탐지하는 데 도움을 주지만 모든 보안 문제를 해결해주는 건 아니라는 점도 중요했다. 특히 프롬프트 인젝션처럼 외부 입력이 Agent의 동작을 바꾸려는 상황은 일반적인 입력값 검증과는 또 다른 문제였다.

이번 주 내용을 돌아보면 새로운 기술을 많이 배웠다기보다, 이미 알고 있던 개발 원칙을 AI Agent 환경에 맞춰 다시 생각해본 느낌이다. 자동화된 테스트와 배포, 명확한 요구사항, 입력 검증은 기존 개발에서도 중요했던 것들이다. 다만 LLM이 중간에 들어가면서 고려해야 할 변수가 더 많아졌다.

기능을 빠르게 구현하는 것도 좋지만, 앞으로는 그 기능이 안전하게 동작하고 반복해서 배포할 수 있는 구조인지도 함께 신경 써야겠다.

✅ 4L

👍 Liked | 좋았던 점

GitHub Actions를 통해 테스트부터 AWS 배포까지 이어지는 흐름을 실습한 게 좋았다. 기존 개발 경험과 연결되는 부분이 많아서 Python 환경에서도 비교적 빠르게 이해할 수 있었다.

🤔 Lacked | 부족했던 점

CI/CD의 전체 구조는 이해했지만 Docker와 AWS 환경 설정은 아직 익숙하지 않다. 문제가 생겼을 때 원인을 찾는 데 시간이 걸리는 부분은 좀 더 경험이 필요할 것 같다.

📚 Learned | 새롭게 배운 점

Moderation API는 가드레일의 일부일 뿐이고, 프롬프트 인젝션 같은 문제는 별도의 방어가 필요하다는 점을 배웠다. JSON과 JSONL도 용도에 따라 구분해서 사용할 수 있다는 걸 정리했다.

🚀 Longed for | 앞으로 더 해보고 싶은 점

개인 프로젝트에도 GitHub Actions를 적용해 테스트와 배포를 자동화해보고 싶다. AI Agent에는 입력 검증과 프롬프트 인젝션 방어도 직접 적용해보면서 어느 정도까지 대응할 수 있는지 확인해보고 싶다.
