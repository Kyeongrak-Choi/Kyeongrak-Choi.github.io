이번 주는 지금까지 배웠던 LLM과 Tool Calling이 조금 더 구체적인 'Agent' 형태로 바뀌기 시작한 시기였다.

create_agent를 살펴보면서 Agent가 단순히 LLM에 이름과 역할을 붙인 정도가 아니라는 점이 먼저 눈에 들어왔다. Instructions를 기본으로 Tool, Memory, Guardrail, 출력 형식까지 하나의 객체 안에서 관리하고, 필요하면 다른 Agent에게 Handoff할 수도 있다. 이전까지 각각 따로 배웠던 개념들이 Agent라는 단위 안으로 모이는 느낌이었다.

특히 단일 Agent와 멀티 Agent의 차이를 구조로 보니 앞으로 배울 내용도 어느 정도 예상할 수 있었다. 무조건 Agent를 여러 개 만드는 게 중요한 게 아니라, 하나의 Agent가 어디까지 책임져야 하고 언제 다른 Agent에게 넘기는지가 더 중요한 문제처럼 보인다. 모바일 개발에서도 객체나 모듈을 나누는 것 자체보다 책임을 어디서 끊을지가 중요했는데, 이쪽도 크게 다르지는 않은 것 같다.

Playwright도 흥미로웠다. 원래 알고 있던 웹 테스트 자동화 도구라는 관점에서 보면 크게 새롭지 않을 수 있지만, Agent와 연결해서 보니 용도가 달라 보였다. LLM이 판단만 하는 게 아니라 실제 브라우저를 열고 정보를 읽거나 버튼을 누르는 식으로 행동할 수 있다. Tool Calling을 배울 때는 '함수를 호출한다'는 느낌이 강했다면, Playwright까지 붙으면서 Agent가 외부 환경에서 실제 작업을 수행한다는 의미가 조금 더 와닿았다.

아직은 각각의 기술을 이해하는 단계라 Agent를 복잡하게 구성하고 싶지는 않다. 오히려 단일 Agent에 몇 개의 Tool을 붙여보고, 책임이 커지는 지점을 직접 경험한 다음 멀티 Agent로 넘어가는 편이 더 맞을 것 같다. 구조를 먼저 복잡하게 만드는 것보다 왜 나눠야 하는지를 알고 나누는 쪽이 내 방식에도 맞는다.

👍 Liked
Tool, Memory, Guardrail처럼 따로 배웠던 개념들이 Agent라는 하나의 구조 안에서 연결되기 시작했다.

🤔 Lacked
멀티 Agent 구조는 이해되지만 아직 직접 부딪혀본 문제가 적어서, 어떤 기준으로 Agent의 책임을 나눌지는 더 경험해봐야 할 것 같다.

📚 Learned
Agent는 LLM에게 역할을 주는 것에서 끝나는 게 아니라, 필요한 도구를 선택하고 실제 행동까지 이어가는 실행 단위에 가깝다. Playwright를 보면서 이 부분이 더 명확해졌다.

🚀 Longed for
우선 단일 Agent에 실제 Tool을 붙여 충분히 만들어보고 싶다. 그 과정에서 복잡해지는 지점을 찾은 뒤 멀티 Agent로 분리해보면 차이를 더 제대로 이해할 수 있을 것 같다.
