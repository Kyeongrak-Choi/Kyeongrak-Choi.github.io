이번 주는 n8n을 이용해 본격적으로 AI Agent를 구현하는 시간이었다. 그동안 외부 API 연동이나 반복적인 업무 자동화 위주로 실습했다면, 이번에는 RAG와 Guardrails, 단일 에이전트와 멀티 에이전트까지 다루면서 이전에 코드 기반으로 배웠던 내용들을 n8n에서 다시 접하게 됐다.

RAG와 Vector DB를 연동하면서 이전에 Python으로 구현했던 방식과 자연스럽게 비교하게 됐다. 직접 코드를 작성할 때는 라이브러리 설정부터 데이터 처리, 검색 흐름까지 신경 써야 했는데, n8n에서는 노드 연결을 통해 비교적 간단하게 구성할 수 있었다. 구현 과정이 줄어드는 건 편했지만, 내부적으로 어떤 처리가 이루어지는지 코드만큼 세밀하게 파악하기 어렵다는 점은 여전히 아쉬웠다.

Guardrails와 Google SMTP 연동, Data Table을 활용한 To-do List 실습도 진행했다. 외부 서비스 연동뿐 아니라 데이터 저장과 AI의 동작 제한까지 하나의 워크플로에서 구성할 수 있다는 점에서 n8n의 활용 범위가 생각보다 넓었다. 다만 실제 서비스로 운영한다면 인증이나 예외 처리, 데이터 관리 등 추가로 고려해야 할 부분은 여전히 많아 보인다.

단일 에이전트와 멀티 에이전트 실습에서는 이전에 배웠던 LangGraph의 구조가 계속 떠올랐다. 영어 도우미를 구현하면서 라우터를 통해 실행 흐름을 나누는 방식도 살펴봤는데, 개발 방식은 달라도 결국 어떤 기준으로 역할을 분리하고 요청을 처리할지 결정하는 과정은 비슷했다. 개인적으로는 복잡한 로직을 직접 코드로 제어하는 방식이 여전히 더 편하다. 그렇지만 짧은 기간에 결과물을 만들어야 한다면 n8n도 충분히 좋은 선택이라고 생각한다.

4단위 프로젝트와 파이널 프로젝트를 앞두고 팀원들과 첫 회의도 진행했다. 프로젝트에 대한 각자의 목표와 참여 방향을 공유했고, 4단위 프로젝트와 파이널 프로젝트는 별도로 주제를 논의하기로 했다. 나 역시 12월부터 취업 준비를 병행할 예정이라 프로젝트의 규모와 역할 분담을 현실적으로 고민해야 할 것 같다.

몇 주간 n8n을 배우면서 처음 가졌던 의문은 어느 정도 해소됐다. 이제는 주어진 실습을 따라가는 것보다 직접 주제를 정하고 필요한 워크플로를 설계해보는 과정이 필요할 것 같다.
