이번 주는 AI Agent의 접근 권한과 RAG의 검색 구조를 조금 더 깊게 살펴본 시간이었다. 이전까지는 Agent가 어떤 Tool을 호출하고 결과를 어떻게 처리하는지에 집중했다면, 이번에는 그 Tool을 누가 사용할 수 있는지, 그리고 필요한 정보를 어떤 방식으로 찾아야 하는지에 관심이 옮겨갔다.

도구와 멀티 에이전트의 역할별 접근 권한을 실습하면서 Agent가 자율적으로 작업한다고 해서 모든 기능에 접근할 수 있도록 만드는 게 맞는지는 다시 생각하게 됐다. 기존 모바일 개발에서도 사용자 권한이나 API 접근 제어는 익숙한 개념이다. 다만 Agent는 스스로 Tool을 선택하고 실행할 수 있다는 점에서 권한을 더 명확하게 구분해야 할 것 같다. 기능을 구현하는 것과 그 기능을 실행해도 되는 상황을 판단하는 건 다른 문제였다.

RAG에서는 Graph RAG와 Hybrid RAG의 차이가 흥미로웠다. 기존에는 임베딩을 이용해 의미적으로 비슷한 문서를 찾는 방식에 익숙해지고 있었는데, 실제 질문에 따라서는 정확한 키워드나 데이터 사이의 관계가 더 중요할 수도 있었다. 특히 Graph RAG는 단순히 관련 문서를 찾는 게 아니라 여러 정보가 어떻게 연결되어 있는지 탐색한다는 점에서 기존 방식과 차이가 있었다.

Neo4j와 Cypher도 함께 살펴봤다. 관계형 데이터베이스는 익숙하지만 노드와 관계를 중심으로 데이터를 구성하는 방식은 아직 낯설다. SQL에서 JOIN으로 연결하던 데이터를 그래프에서는 관계 자체로 표현한다는 점이 인상적이었다. 머릿속에서는 자꾸 기존 DB 구조로 먼저 생각하게 되는데, 이런 부분은 직접 데이터를 만들어보고 조회해봐야 더 명확해질 것 같다.

사이킷런과 Colab도 알아봤지만, 아직은 어떤 역할을 하는지 이해한 정도다. Python으로 머신러닝 모델을 다루는 영역은 기존에 해왔던 개발과는 거리가 있어서 당장 익숙해지기는 어렵다. 그래도 AI Agent를 개발하면서 모델을 활용하는 것과 모델 자체를 학습시키는 일이 어떻게 다른지는 조금씩 구분되고 있다.

이번에 배운 기술들을 모두 적용할 필요는 없다고 생각한다. 오히려 어떤 문제가 있을 때 어떤 방식을 선택해야 하는지 판단할 수 있는 게 더 중요하다. RAG도 무조건 복잡한 구조를 도입하기보다는 실제 데이터와 질문의 특성을 먼저 확인해보고 싶다.

✅ 4L

👍 Liked | 좋았던 점

기존에 알고 있던 API 권한 관리나 데이터베이스 개념을 AI Agent에 연결해서 생각해볼 수 있었다. 특히 Graph RAG는 기존 RAG와 접근 방식이 달라서 흥미로웠다.

🤔 Lacked | 부족했던 점

Neo4j와 Cypher는 개념을 이해한 정도라 실제로 데이터를 구성하고 관계를 조회하는 과정은 아직 익숙하지 않다. 검색 방식별로 어떤 상황에서 더 좋은 결과가 나오는지도 직접 비교해보지 못했다.

📚 Learned | 새롭게 배운 점

Hybrid RAG는 키워드와 의미 기반 검색을 결합하고, Graph RAG는 데이터 사이의 관계를 활용한다는 차이를 정리했다. Agent의 Tool 접근 권한 역시 실행 흐름과 별도로 설계해야 한다는 점을 다시 생각하게 됐다.

🚀 Longed for | 앞으로 더 해보고 싶은 점

같은 데이터를 대상으로 일반 RAG와 Hybrid RAG의 검색 결과를 비교해보고 싶다. Neo4j로 간단한 관계 데이터를 구성한 뒤 Cypher로 직접 조회해보는 것도 해볼 생각이다.
