이번 주는 개별 기술을 배우는 것보다, 하나의 서비스를 구성할 때 필요한 요소들이 어떻게 연결되는지를 조금씩 보기 시작한 한 주였다.

FastAPI와 Supabase를 연결하고 사용자 조회·수정·삭제, 대화 생성과 조회까지 구현하면서 단순 API 작성에서 한 단계 더 들어갔다. 특히 Supabase Auth와 RLS를 같이 보면서 인증과 권한이 별개의 기능이 아니라는 점이 명확해졌다. 로그인해서 JWT를 받는 것으로 끝나는 게 아니라, 결국 그 사용자가 어떤 데이터까지 접근할 수 있는지를 DB 수준에서도 제어해야 한다. 모바일 개발에서도 인증은 익숙하게 다뤄왔지만, 백엔드와 데이터베이스 관점에서 직접 연결해보니 구조가 좀 더 구체적으로 보였다.

중반부터는 Redis가 등장하면서 데이터 저장 방식도 생각보다 선택지가 많다는 걸 느꼈다. 특히 Redis는 단순히 빠른 DB 정도로 생각했는데 String, Hash, List, Set 같은 자료구조와 TTL을 직접 보고 나니 캐시나 세션처럼 왜 특정 상황에 사용하는지가 조금 이해됐다. Supabase와 Redis를 같이 연결해본 것도 좋았다. 한 가지 DB로 모든 문제를 해결하기보다는 역할에 맞게 도구를 나누는 쪽이 자연스럽다는 생각이 들었다.

후반에는 분위기가 꽤 달라졌다. IA, User Flow, Wireframe을 만들고 Streamlit으로 화면을 구성하면서 그동안 백엔드에서 만든 기능을 사용자가 실제로 어떻게 접하게 되는지 생각하게 됐다. 앱을 오래 개발해서 UI 자체는 낯설지 않지만, Python 코드만으로 빠르게 화면을 만들 수 있다는 점은 의외로 재미있었다. 완성도 높은 제품 UI라기보다는 AI 기능이나 아이디어를 빠르게 검증하는 용도로는 꽤 실용적으로 보인다. Pandas도 처음 접했는데, 지금 단계에서는 깊게 파기보다 데이터를 다루는 기본 도구로 익숙해지는 정도면 충분할 것 같다.

이번 주를 지나면서 FastAPI, Supabase, Redis, Streamlit이 각각 따로 떨어진 기술처럼 느껴지지는 않는다. 아직 하나하나 능숙한 단계는 아니지만, 인증부터 데이터 저장, 캐시, 화면까지 한 서비스가 만들어지는 흐름은 조금 보이기 시작했다. 다음에는 새로운 기술을 더 늘리는 것보다 지금까지 배운 것들을 하나의 작은 프로젝트 안에서 실제로 연결해보는 편이 더 도움이 될 것 같다.

✅ 4L

👍 Liked
Supabase와 FastAPI를 연결한 뒤 Redis, Streamlit까지 이어지면서 배우는 내용들이 처음으로 하나의 서비스 구조처럼 보이기 시작했다.

🤔 Lacked
Redis나 Elasticsearch처럼 새로 접한 기술은 아직 어디에 써야 하는지는 알겠지만, 어느 시점에 실제로 도입해야 하는지 판단할 정도는 아니다.

📚 Learned
인증, 권한, DB, 캐시, UI는 각각 독립된 기능이 아니라 결국 하나의 사용자 흐름 안에서 연결되어야 한다는 점이 가장 크게 남았다.

🚀 Longed for
새로운 개념을 계속 추가하기보다 FastAPI + Supabase + Redis + Streamlit 조합으로 작은 서비스를 처음부터 끝까지 직접 만들어보고 싶다.
