이번 주는 교육 과정에서 처음으로 '배운 것을 실제 결과물로 만드는 과정'을 제대로 경험한 한 주였다. 3일 동안 팀 프로젝트를 진행하면서 단순히 기능을 구현하는 것보다, 제한된 시간 안에서 어떤 기능을 우선순위에 둘지, 팀원들과 어떻게 역할을 나누고 연결할지가 더 중요하다는 걸 느꼈다. 혼자 개발할 때는 내가 원하는 방향으로 바로 수정하면 됐지만, 팀 프로젝트에서는 다른 사람의 작업과 맞물리는 구조를 먼저 생각해야 했다.

이번 프로젝트에서는 LLM 파트를 맡으면서 단순히 Gemini를 호출하는 수준이 아니라, AI 기능을 어떻게 서비스 안에 자연스럽게 녹여낼지 계속 고민했다. 프롬프트를 어떻게 구성할지, 응답 형식을 어떻게 통일할지, 다른 기능들과 어떤 방식으로 연결해야 유지보수가 쉬울지를 생각하면서 구현하다 보니, 'AI 기능 하나'를 만드는 것이 아니라 하나의 시스템을 설계한다는 느낌이 더 강했다. 프로젝트를 준비하면서 미리 구조를 고민하고 선수작업을 해둔 것이 실제 개발에서는 생각보다 큰 도움이 됐다.

프로젝트가 끝난 뒤에는 고급 프롬프팅 전략을 배우기 시작했다. 이전까지는 프롬프트를 잘 작성하는 것이 핵심이라고 생각했는데, 이제는 역할 부여, 컨텍스트 구성, 출력 형식 제한, 단계적 추론 유도처럼 원하는 결과를 얻기 위한 설계 방법이 훨씬 중요하다는 걸 알게 됐다. 결국 좋은 결과는 모델 자체보다 어떤 정보를 어떤 순서로 전달하느냐에 더 크게 영향을 받는다는 점이 인상적이었다.

이번 주를 지나면서 앞으로의 방향도 조금 더 명확해졌다. 지금까지는 Python, FastAPI, Supabase, LLM을 각각 배우는 과정이었다면, 이제는 이것들을 하나의 AI Agent 서비스로 연결하는 단계에 들어온 것 같다. 프로젝트를 한 번 경험하고 나니 부족한 부분도 많이 보였지만, 동시에 어떤 부분을 더 공부해야 할지도 훨씬 선명해졌다.

✅ 4L

👍 Liked
프로젝트를 통해 배운 기술들이 실제 서비스 형태로 연결되는 경험을 할 수 있었다. 특히 LLM 파트를 맡으면서 단순 구현보다 설계의 중요성을 많이 느꼈다.

🤔 Lacked
짧은 개발 기간이다 보니 기능 완성에 집중하게 되었고, 코드 구조를 충분히 다듬거나 다양한 방법을 시도해볼 여유는 부족했다.

📚 Learned
고급 프롬프팅은 질문을 잘 쓰는 기술이 아니라, AI가 안정적으로 원하는 결과를 내도록 전체 흐름을 설계하는 과정이라는 점을 배웠다.

🚀 Longed for
다음 프로젝트에서는 이번 경험을 바탕으로 단일 Agent를 넘어 여러 Agent가 협력하는 구조까지 직접 설계하고 구현해보고 싶다.
