> 유튜브 시청 기록이나 기존 추천 알고리즘이 아닌, 사용자가 직접 입력한 조건을 기준으로 필요한 영상을 추천하는 서비스

## 1. 프로젝트 선정 배경
 
유튜브 추천 알고리즘을 이용하다 보면 처음에 찾으려던 내용과 관계없는 쇼츠나 동영상을 계속 보게 되는 경우가 있다. 이로 인해 의도하지 않게 시청 시간이 늘어나거나, 정작 필요한 콘텐츠를 찾는 데 집중하기 어려워지기도 한다.
 
이러한 문제를 줄이기 위해 추천 알고리즘을 끄고 구독한 채널의 새 영상이나 필요한 주제를 직접 검색해 보았지만, 구독하지 않은 채널의 좋은 콘텐츠를 발견하기 어렵다는 한계가 있었다.
 
YouPick은 기존 유튜브 알고리즘에서 벗어나, 사용자가 현재 입력한 요청과 조건에 맞는 영상만 선별해 추천받고 싶다는 생각에서 시작한 프로젝트다.
 
----------------------------------------------------------------------------

## 2. 프로젝트 목적
 
YouPick의 목적은 유튜브 알고리즘 전체를 대체하는 것이 아니라, 사용자의 현재 의도를 반영한 영상 탐색 환경을 제공하는 것이다.
 
- 과거 시청 기록에 의존하지 않고 현재 입력한 조건으로 영상을 찾는다.
- 사용자가 원하지 않는 콘텐츠 탐색을 줄인다.
- 구독 여부와 관계없이 조건에 맞는 새로운 영상을 발견할 수 있게 한다.
- 단순 검색 결과가 아닌 추천 이유가 포함된 결과를 제공한다.

----------------------------------------------------------------------------

## 3. 서비스 개요

사용자는 다음 네 가지 정보를 입력한다.

- **카테고리:** 영상의 큰 주제 영역을 선택한다. 예: 과학, 테크·IT, 경제·주식
- **상세 요청:** 찾고 싶은 내용을 자연어로 입력한다. 예: FastAPI와 Supabase 로그인 구현
- **시간 제한:** 시청 가능한 최대 영상 길이를 선택한다. 예: 30분 이내
- **시청 목적:** 영상을 통해 얻고 싶은 결과를 선택한다. 예: 빠른 요약, 개념 이해, 심층 분석, 실습

입력 조건을 받은 서비스는 YouTube에서 후보 영상을 찾은 뒤, 조건과 관련성이 높은 영상을 상위에 배치한다. 프로젝트의 선정 배경을 반영하여 Shorts는 기본적으로 추천 대상에서 제외한다.

추천 결과에는 영상 제목, 채널명, 썸네일, 영상 길이, 업로드 날짜와 함께 해당 영상을 추천한 이유를 표시한다.

## 4. 데이터 수집과 추천 방식

처음부터 대규모 데이터셋을 구축하지 않고, 사용자가 검색할 때 YouTube API를 통해 필요한 후보 영상을 수집한다.

- **사용자 입력**
  - 수집 데이터: 카테고리, 상세 요청, 시간 제한, 시청 목적
  - 활용 목적: 영상 검색 및 추천 기준으로 사용

- **YouTube 검색 API (`search.list`)**
  - 수집 데이터: 영상 제목, 설명, 채널, 영상 ID
  - 활용 목적: 후보 영상을 구성하고 `videoDuration`으로 영상 길이를 1차 필터링

- **YouTube 영상 API (`videos.list`)**
  - 수집 데이터: 태그, 영상 길이, 조회수, 업로드 날짜
  - 활용 목적: 시간 조건을 다시 확인하고 추천에 필요한 상세정보 수집

- **AI 분석**
  - 생성 데이터: 영상 성격, 추천 이유
  - 활용 목적: 사용자 요청과 영상의 적합성을 분석하고 추천 이유 제공
 
추천 과정은 다음과 같이 구성한다.
 
```text
사용자 조건 입력
→ search.list로 후보 영상 검색 (videoDuration으로 1차 시간 필터링)
→ videos.list로 태그·길이·조회수 등 상세정보 조회
→ Shorts 판별 및 제외, 시간 제한 재확인
→ 요청 내용과 영상 정보 비교
→ 관련성이 높은 영상 정렬
→ 추천 이유와 함께 결과 제공
```

## 5. 참고사항 

### Shorts 판별 방식
 
YouTube Data API에는 영상이 Shorts인지 여부를 직접 알려주는 필드가 없다. 따라서 `videos.list`로 조회한 `contentDetails.duration`이 60초 이하인 경우를 Shorts로 간주하는 방식을 사용한다. 완벽한 판별은 아니지만 현재 API 환경에서 가장 널리 쓰이는 방법이다.
 
### API 제한사항
 
YouTube Data API는 `search.list` 호출당 100유닛, `videos.list` 호출당 1유닛이 소요되며, 기본 할당량은 프로젝트당 하루 10,000유닛이다.
 
YouPick은 한 번의 사용자 요청당 다음과 같이 API를 소비한다.
 
- `search.list` 1회: 100유닛
- 후보 15~20개에 대한 `videos.list` 조회: 15~20유닛
- 요청당 합계: 약 115~120유닛
따라서 기본 할당량으로 처리 가능한 사용자 요청은 하루 약 **83~87회** 수준이며, `search.list` 자체의 호출 한도(100회)만으로 판단하면 실제 처리 가능 요청 수를 과대평가하게 된다. 동일한 검색 조건의 결과는 Redis에 캐싱하여 반복 호출을 줄이고, 캐시 키는 우선 카테고리·시간 제한·시청 목적 조합으로 구성한다. 상세 요청(자연어)은 표현이 달라지면 동일한 의도라도 캐시가 히트하지 않을 수 있으므로, 이후 임베딩 유사도 기반 매칭으로 확장하는 것을 다음 단계 과제로 둔다.
 
또한 일일 쿼터는 태평양 표준시(PT) 자정에 초기화되며, 이는 한국 시간 기준 오후 4~5시경에 해당한다. 국내 사용자 트래픽이 몰리는 저녁~밤 시간대와 리셋 시점이 어긋나므로, 트래픽 패턴을 고려한 쿼터 소진 계획이 필요하다. 트래픽이 늘어나 기본 할당량을 초과할 경우 Google Cloud Console에서 쿼터 증설을 신청할 수 있다.
