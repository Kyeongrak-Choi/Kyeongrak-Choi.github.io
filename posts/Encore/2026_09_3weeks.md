이번 주는 AI를 활용하는 방법을 배우는 단계에서, AI가 실제로 어떻게 동작하는지 한 단계 더 깊게 이해한 시간이었다. 특히 Tool Calling과 MCP(Model Context Protocol)를 배우면서 LLM이 단순히 답변만 생성하는 모델이 아니라, 외부 도구와 연결되어 실제 작업을 수행하는 구조를 조금씩 이해하게 됐다. 이전에는 API를 호출하는 정도로만 생각했다면, 이제는 모델이 어떤 기준으로 도구를 선택하고 결과를 다시 받아 응답을 만드는지 전체 흐름이 머릿속에 그려지기 시작했다.

가장 흥미로웠던 부분은 Function Calling과 MCP의 역할을 비교해본 것이었다. 처음에는 둘이 비슷한 기술이라고 생각했지만, 직접 구조를 살펴보니 Function Calling은 모델이 정해진 함수를 호출하는 방식에 가깝고, MCP는 다양한 도구와 리소스를 표준화된 방식으로 연결하는 인터페이스라는 차이가 있었다. 앞으로 AI Agent를 만든다면 단순히 모델을 호출하는 것보다 도구를 어떻게 연결하고 관리할지가 더 중요하다는 생각이 들었다.

이번 주에는 Tool Calling을 직접 구현하면서 메시지 흐름도 다시 정리해봤다. 사용자의 질문을 전달하고, 모델이 필요한 도구를 선택하면 실제 함수를 실행한 뒤 결과를 다시 모델에게 전달하는 과정이 생각보다 단순하면서도 명확했다. 처음에는 코드가 길어 보여 어렵게 느껴졌지만, 하나씩 따라가면서 보니 결국 LLM도 입력과 출력, 그리고 상태를 관리하는 하나의 애플리케이션이라는 점은 기존 개발과 크게 다르지 않았다.

한편으로는 새로운 프로젝트 아이디어도 계속 고민했다. 단일 기능을 만드는 것보다 AI가 사용자의 계획을 검증하고 질문을 이어가는 형태의 서비스처럼, Agent의 특성을 살릴 수 있는 방향을 생각하게 됐다. 배우는 기술이 늘어날수록 무엇을 더 공부해야 하는지보다, 어디에 적용하면 좋을지가 더 많이 떠오르기 시작한 것도 이번 주의 변화였다.

✅ 4L

👍 Liked
Tool Calling과 MCP를 배우면서 AI Agent가 실제로 동작하는 구조를 이해할 수 있었고, 막연했던 개념들이 조금씩 연결되기 시작했다.

🤔 Lacked
개념은 이해했지만 아직 직접 구현해본 경험은 많지 않아, 복잡한 Agent 구조를 혼자 설계하기에는 경험이 더 필요하다는 걸 느꼈다.

📚 Learned
LLM의 성능은 모델 자체뿐 아니라 Tool Calling, Context 관리, 외부 시스템과의 연결 방식까지 포함한 전체 구조에 영향을 받는다는 점을 배웠다.

🚀 Longed for
MCP와 Tool Calling을 활용해 여러 도구가 협력하는 멀티 에이전트를 직접 구현해보고, 실제 서비스 형태까지 발전시켜 보고 싶다.
