이번 주는 n8n을 배우면서 AI Agent를 개발하는 방식에 대해 다시 생각해본 시간이었다. 지금까지는 Python과 LangGraph를 이용해 직접 코드를 작성하는 방식에 익숙해지는 중이었는데, n8n은 노드를 연결하는 것만으로 실행 흐름을 구성할 수 있다는 점에서 접근 방식이 꽤 달랐다.

처음에는 코드를 직접 작성하지 않는 방식이 얼마나 유용할지 조금 의문이었다. 기존에 개발을 오래 해왔고, LangGraph로 Agent를 구현해본 경험도 있어서 굳이 시각적인 도구를 사용해야 할 이유가 있을까 싶었다. 그런데 데이터 이동과 분기, 필터, 스케줄 실행 등을 실습하면서 생각이 조금 달라졌다. 특히 Google News를 정해진 시간에 가져오는 자동화처럼 흐름이 명확한 작업은 직접 서버를 구성하고 코드를 작성하는 것보다 훨씬 간단하게 구현할 수 있었다.

반대로 복잡한 비즈니스 로직이나 세밀한 상태 관리가 필요한 상황에서는 여전히 코드 기반 개발이 더 편할 것 같았다. 모바일 개발을 하면서 조건 분기나 예외 처리를 코드로 관리하는 데 익숙해진 영향도 있을 것이다. n8n에서도 다양한 처리가 가능하지만, 노드가 많아지고 흐름이 복잡해졌을 때 유지보수는 어떨지 궁금해졌다.

ngrok도 함께 살펴봤다. 로컬에서 실행 중인 서버를 외부 서비스와 연결할 수 있다는 점은 알고 있으면 유용할 것 같다. 이전 프로젝트에서는 API를 테스트하기 위해 서버를 배포했는데, 개발 단계에서 단순히 외부 연동을 확인하는 목적이라면 굳이 배포하지 않아도 되는 상황이 있겠다는 생각이 들었다.

이번 주에는 코드 기반과 로우코드 기반 중 어느 쪽이 실무에서 더 많이 사용되는지도 찾아봤다. 처음에는 AI Agent 개발자로 취업하려면 LangGraph 같은 프레임워크를 깊게 다루는 게 무조건 유리하다고 생각했는데, 실제로는 서비스의 목적에 따라 필요한 기술이 달랐다. 복잡한 Agent 로직은 코드로 구현하고, 외부 서비스 연동이나 반복적인 업무는 n8n으로 처리하는 방식도 충분히 합리적으로 보였다.

다만 아직 n8n은 기본적인 노드와 실행 흐름을 익힌 단계라 LangGraph와 어느 정도까지 비교할 수 있을지는 모르겠다. 직접 복잡한 워크플로를 만들어보면 장단점이 더 명확해질 것 같다. 당장은 하나를 선택하기보다 각각 어떤 상황에서 효율적인지 판단할 수 있을 정도로 익혀두는 게 목표다.

✅ 4L

👍 Liked | 좋았던 점

n8n으로 데이터 이동과 조건 분기, 스케줄 자동화를 직접 구성해본 게 좋았다. 코드를 작성하지 않고도 빠르게 결과를 확인할 수 있다는 점은 확실한 장점이었다.

🤔 Lacked | 부족했던 점

아직 기본적인 기능 위주로 실습해서 복잡한 Agent를 n8n으로 구현했을 때의 한계는 잘 모르겠다. 노드가 많아졌을 때 디버깅이나 유지보수가 어떻게 달라지는지도 궁금하다.

📚 Learned | 새롭게 배운 점

n8n은 단순한 자동화 도구를 넘어 AI Agent와 외부 서비스를 연결하는 데도 활용할 수 있다. ngrok을 이용하면 로컬 서버를 외부에서 호출할 수 있다는 점도 정리했다.

🚀 Longed for | 앞으로 더 해보고 싶은 점

LangGraph로 구현했던 Agent를 n8n으로도 간단하게 만들어보고 싶다. 같은 기능을 두 방식으로 구현해보면 개발 속도와 구조적인 차이를 좀 더 객관적으로 비교할 수 있을 것 같다.
